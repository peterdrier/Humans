---
name: Moved pages take their new owner's URLs
description: When a page or action moves to another section, it takes that section's own route — never keep the old URL, never add a redirect or alias from it.
---

A page or action that moves to another section takes the new owner's own route (`/<Section>/...`; admin pages `/<Section>/Admin/...`). Do not keep the old prefix on the new controller, and do not add a redirect or alias from the old URL.

**Why:** Peter, 2026-10-21, during the Users decomposition: *"moving facilitated messaging should not keep the url, DO NOT keep urls. a move is a move. bookmarks are not a thing we worry about anymore."* A kept prefix (`/Profile/Me/*` on a Cantina controller) leaves the URL claiming an owner the code no longer has.

**How to apply:**

- Moving a controller or action: change its route to the owner's tree, update every link, test, allowlist and doc that names the old path, and delete any legacy redirect for it.
- Links generated by `asp-controller`/`asp-action`/`Url.Action` follow by name; literal paths (docs, guide, JS, e2e helpers, agent prompts) need hand edits.
- No exception for URLs in already-sent emails, mail headers (`List-Unsubscribe`) or external systems: those links break too (Peter, 2026-10-21). Update the code that mints them and report any external system that must change.
- Not a licence to churn routes that never moved (e.g. pages that predate the move under another section's prefix) in unrelated work.

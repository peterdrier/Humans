## architecture/

- [`audit-log-as-concurrency-safety-net`](architecture/audit-log-as-concurrency-safety-net.md) — When a reviewer flags a lost-update race on an audited entity, the audit log is the safety net — don't add `IsConcurrencyToken`/row versioning or redesign the repo.
- [`base-ui-registries-are-section-populated`](architecture/base-ui-registries-are-section-populated.md) — When a Base `Humans.UI` registry (EnumBadgeMap etc.) needs a section's enum, have the section push rows via `Section.Register` — Base never references the section's contracts.
- [`background-db-work-after-migration-barrier`](architecture/background-db-work-after-migration-barrier.md) — DB-touching background workers (timers/pollers/pre-warmers) must arm in `IHostedService.StartAsync`, never a constructor `Timer` or eager pre-`app.Run()` `GetRequiredService`.
- [`burnername-is-the-display-name`](architecture/burnername-is-the-display-name.md) — HARD RULE. Only `User.BurnerName` renders the name (via `<vc:human>`, `UserInfo.BurnerName`) — never read `DisplayName` directly.
- [`books-start-2026`](architecture/books-start-2026.md) — Nobodies Collective's Holded accounting books begin in 2026 — a single fiscal year, so no cross-year reasoning (key collisions, rollover, prior-year comparatives) applies.
- [`caching-transparent`](architecture/caching-transparent.md) — When naming a cached DTO, never use `Cached*` — consumers shouldn't know data came from cache. Use canonical names like `TeamInfo` or established ones like `FullProfile`.
- [`cached-reads-no-shape-variants`](architecture/cached-reads-no-shape-variants.md) — When a read serves from a fully-populated in-memory cache, don't add shape variants (`WithEmails`, `IncludeFoo`) — the cache holds one shape; that's EF-shaped thinking leaking in.
- [`cancellation-token-propagation`](architecture/cancellation-token-propagation.md) — Never pass a request-scoped `CancellationToken` into an outbound call mutating a third party — read-only GETs may keep it. HUM0033 + `[ExternalWrite]` enforce this.
- [`consent-record-immutable`](architecture/consent-record-immutable.md) — The `consent_records` table has DB triggers preventing UPDATE and DELETE. Only INSERT. New consent state = new row. Required for GDPR audit trail integrity.
- [`datetime-format-single-home`](architecture/datetime-format-single-home.md) — HARD RULE. Custom date/time format strings live only in `DateFormattingExtensions` — call a named formatter, never inline a literal. Enforced by HUM0030.
- [`db-enforcement-minimal`](architecture/db-enforcement-minimal.md) — Don't design around DB constraints — only `audit_log`/`consent_records` immutability triggers are doctrinal. CHECK constraints are banned; NOT NULL isn't enforcement.
- [`debug-section`](architecture/debug-section.md) — Developer/diagnostics pages live in the Debug section at /Debug/* (DebugController, AdminOnly) — forward home for logs, db/cache stats, client stats. Not /Admin/*.
- [`decorators-talk-only-to-inner`](architecture/decorators-talk-only-to-inner.md) — HARD RULE. A caching decorator over interface I depends only on I (its keyed inner) and cache plumbing — no sideways repo, service, or sibling-section injections.
- [`derived-predicates-on-userinfo`](architecture/derived-predicates-on-userinfo.md) — Derived user predicates (IsActive, IsStub, NeedsConsentReview, etc.) go on `UserInfo`, never on `ProfileInfo` or `Profile` — ProfileInfo stays a flat field projection.
- [`display-sort-in-controllers`](architecture/display-sort-in-controllers.md) — Display ordering belongs in controllers/views, not services or repos. Repo-layer `OrderBy` is allowed only for tie-breakers/top-N/chronological streams, marked `// arch:db-sort-ok`.
- [`email-templates-live-in-sender`](architecture/email-templates-live-in-sender.md) — Adding or editing an email template: build it in the sending section (own resx, own tests, an IEmailPreviewContributor), never in the Email crosscut.
- [`every-human-has-an-email`](architecture/every-human-has-an-email.md) — HARD RULE — every human has an email, period. Never design for, defend against, or file findings about an emailless user; treat a no-email code path as unreachable.
- [`fanout-spokes-name-themselves`](architecture/fanout-spokes-name-themselves.md) — When adding to or changing a fanout interface (hub iterates `IEnumerable<IContract>`), never add a central constant/enum/type list naming which sections participate — spokes declare their own facts, tests derive the roster by reflection.
- [`gdpr-is-a-feature-not-a-lens`](architecture/gdpr-is-a-feature-not-a-lens.md) — HARD RULE. Our own in-process code reading personal data is NEVER a GDPR concern: metrics, full-population reads, snapshots, caches, wide DTOs. "This caller sees more personal data than it needs" is not a finding — never raise it. The GDPR features (consent gates, export contributors, deletion paths) and anything leaving the system stay fully in scope.
- [`google-service-account-bare-auth`](architecture/google-service-account-bare-auth.md) — HARD RULE. The Google Workspace service account authenticates as itself — no domain-wide delegation or impersonation. Never propose adding DWD when a Google API call fails.
- [`hum0031-frozen-until-2027`](architecture/hum0031-frozen-until-2027.md) — HARD RULE. HUM0031's 40/15 controller-method thresholds are frozen until 2027 — never propose tightening, unfreezing, or re-evaluating them, even as a question.
- [`section-list-from-di`](architecture/section-list-from-di.md) — Before hand-writing a list of section names — in code, in a doc, or in a skill's ledger — inject `ISectionCatalog` or glob `src/Sections/Humans.*`. No app-wide roster of sections in prose either. A deliberate subset publishes `ISectionAnnotations` so drift shows.
- [`team-resources-google-integration-section`](architecture/team-resources-google-integration-section.md) — ITeamResourceService and TeamResourceService live in the Humans.GoogleIntegration section project even though google_resources is a Team Resources sub-aggregate.
- [`tier-derived-from-applications`](architecture/tier-derived-from-applications.md) — Tier (Colaborador/Asociado) is derived from an Approved Application with an active term — no tier-locking domain rule; the only boundary is no-duplicate-Submitted on `SubmitAsync`.
- [`interface-method-additions-are-debt`](architecture/interface-method-additions-are-debt.md) — Adding a method to any interface is durable debt. Audit existing methods first — prefer a LINQ chain at the call site over a new method. Stop and ask Peter before adding one.
- [`iuserservice-onestop-userinfo`](architecture/iuserservice-onestop-userinfo.md) — Long-term direction: `IUserService` is the one-stop-shop for every `UserInfo` field, reads and writes — prefer it for new callers; sibling services drain into it over time.
- [`migration-regen-after-rebase`](architecture/migration-regen-after-rebase.md) — HARD RULE. Once main's migrations interleave with yours (mid-chain), `dotnet ef migrations remove` is broken — stop and ask Peter; never hand-edit the snapshot or reset+redo.
- [`no-admin-url-section`](architecture/no-admin-url-section.md) — HARD RULE. Top-level `/Admin/*` is legacy; never add new `/Admin/foo` routes. New admin pages always live at `/<Section>/Admin/*`.
- [`no-business-logic-in-controllers`](architecture/no-business-logic-in-controllers.md) — Controllers parse input, authorize, dispatch, and return — no domain branching or orchestration. HUM0031 errors on any controller method over 40 statements or complexity 15.
- [`no-column-drops-for-decoupling`](architecture/no-column-drops-for-decoupling.md) — HARD RULE. When decoupling code from a column, a property override plus read sweeps completes the work — the column drop is separate, optional, and waits for prod verification.
- [`no-concurrency-tokens`](architecture/no-concurrency-tokens.md) — HARD RULE. Never add `IsConcurrencyToken()`, `[ConcurrencyCheck]`, or row versioning to any entity — single-server scale means conflicts don't happen; ask Peter before adding any.
- [`unique-constraints-ids-only`](architecture/unique-constraints-ids-only.md) — HARD RULE. Row identity/uniqueness rests on Id columns only — never a unique index on a name, slug, or any user-editable string; seed code finds rows by Id, never `WHERE Name = ...`.
- [`no-cross-section-ef-joins`](architecture/no-cross-section-ef-joins.md) — HARD RULE. A section's EF model joins only its own tables — no `HasOne`/nav properties/FK constraints across sections. Cross-section linkage is a bare Guid column.
- [`no-db-check-constraints`](architecture/no-db-check-constraints.md) — HARD RULE. Never add a CHECK constraint to the forward model (`HasCheckConstraint`, hand-written SQL) — enforce invariants in service code instead. Triggers are unaffected.
- [`no-drops-until-prod-verified`](architecture/no-drops-until-prod-verified.md) — HARD RULE. Dropping DB columns/tables/indexes or persisted files needs a written description, evidence of no in-use readers, and Peter's per-case approval — code deletions are exempt.
- [`no-hand-edited-migrations`](architecture/no-hand-edited-migrations.md) — HARD RULE. EF migrations and every `*DbContextModelSnapshot.cs` must be 100% auto-generated and committed verbatim — no hand edits, ever. Pre-commit hook enforces migration files.
- [`never-block-signin`](architecture/never-block-signin.md) — HARD RULE. Sign-in must always succeed once Identity authenticates the user. Never propose flows that block sign-in for data-cleanup or conflict-resolution reasons.
- [`no-linq-at-db-layer`](architecture/no-linq-at-db-layer.md) — Prefer hand-written repo methods materializing at the boundary over `IQueryable` composed across services — LINQ on EF-mapped properties scatters DB-shape concerns.
- [`analyzer-exceptions-via-attributes`](architecture/analyzer-exceptions-via-attributes.md) — To grandfather an analyzer violation, use `[Grandfathered("HUM####",...)]` on the declaration only — never baselines, editorconfig overrides, allowlists, or suppressions.
- [`dontfix-attribute`](architecture/dontfix-attribute.md) — `[DontFix]` marks a permanent, Peter-only analyzer exception — agents may add `[Grandfathered]` (debt) but must never add `[DontFix]` themselves.
- [`universal-enforcement-over-per-section`](architecture/universal-enforcement-over-per-section.md) — When adding/reviewing an architecture analyzer or arch test, it must be universal (derived from a hard rule), never per-section — a per-section enforcer or workaround is itself a smell.
- [`no-tests-for-absences`](architecture/no-tests-for-absences.md) — Never write a per-section test asserting a section lacks something (no repo, DbContext, nav property), and never ask Peter whether a section is missing one — absence has no behaviour to regress. Repo-wide universal enforcers are exempt.
- [`no-startup-guards`](architecture/no-startup-guards.md) — HARD RULE. The app must always boot — no startup checks that throw or refuse to register services. Fix at runtime, via an admin button, or an idempotent migration.
- [`one-ifilestorage`](architecture/one-ifilestorage.md) — HARD RULE — one shared `IFileStorage`, key-namespaced under `uploads/`, rooted at `wwwroot/`. Never introduce a per-domain storage interface or a parallel filesystem root.
- [`orchestrator-sections-reference-orchestrated`](architecture/orchestrator-sections-reference-orchestrated.md) — A section that orchestrates others (Search, Dashboard) referencing those sections is expected and fine — the only hard constraint is no cycles; don't flag the edge as a smell.
- [`person-search`](architecture/person-search.md) — HARD RULE. Person search routes only through `IUserServiceRead.SearchUsersAsync`, rendered via `<vc:human-search>`/`<vc:user-search-result>`. Emergency contacts aren't searchable.
- [`provenance-fks-not-user-scoped`](architecture/provenance-fks-not-user-scoped.md) — A section can carry user FK columns (AddedByUserId, etc.) without being user-scoped — don't reflexively demand `IUserDataContributor` for every per-user FK; apply the deletion test
- [`refunds-manual-via-dashboard`](architecture/refunds-manual-via-dashboard.md) — HARD RULE. Humans never calls Stripe refund/payout APIs — money-out is human-initiated on stripe.com; the app only bookkeeps via negative `StorePayment` rows.
- [`required-columns-need-approval`](architecture/required-columns-need-approval.md) — HARD RULE. Never add a `NOT NULL` column to an existing table without Peter's per-instance approval — default to nullable; declare any approved default in the model too.
- [`read-model-enrichment`](architecture/read-model-enrichment.md) — When a caller needs stable facts about an aggregate already on a canonical read model (`UserInfo`, `TeamInfo`), add scalar fields to that DTO instead of a new service method.
- [`repository-required-for-db-access`](architecture/repository-required-for-db-access.md) — HARD RULE. Every DB-accessing service goes through a repository deriving from `IRepository` — no service injects a DbContext directly, even for a singleton-row table.
- [`section-contribution-seams`](architecture/section-contribution-seams.md) — When adding a nav link, admin tile, job, or health check, implement it as an `ISectionContribution` seam on `Section` — never a by-name edit to a Shell composition class.
- [`section-controllers-need-feature-provider`](architecture/section-controllers-need-feature-provider.md) — An `internal` section controller 404s silently — MVC's `ControllerFeatureProvider` requires `IsPublic`. `SectionControllerFeatureProvider` in Shell relaxes that check for sections.
- [`section-project-cycle-fix`](architecture/section-project-cycle-fix.md) — When MSBuild refuses a section reference as circular, carve `<Section>.Contracts` out of the upstream section — never promote the shared type into Base to dodge the cycle.
- [`section-read-write-split`](architecture/section-read-write-split.md) — A section consumed cross-section exposes `I<Section>ServiceRead` (DTO-only reads); writes, cache hooks, and section-internal reads stay on the full `I<Section>Service`.
- [`service-read-no-ef`](architecture/service-read-no-ef.md) — Cross-section `I*Read` interfaces expose DTO/Info projections only — no EF entities, no `Microsoft.EntityFrameworkCore` types, no `IQueryable`.
- [`no-leaf-to-director-callbacks`](architecture/no-leaf-to-director-callbacks.md) — Reject any ctor/call edge where a leaf service (ProfileService, ConsentService) reaches up to a director (OnboardingService, etc.) — director-to-leaf is one-way only.
- [`section-identity-is-the-assembly`](architecture/section-identity-is-the-assembly.md) — A section is an assembly declaring `Section : ISection`; its name is the assembly name minus `Humans.` and any `.Contracts` suffix. There is no separate section attribute.
- [`sections-are-logical-units`](architecture/sections-are-logical-units.md) — A section is a logical, independently-workable unit — owning DB tables is not required. Never propose demoting or merging a section for being thin or table-less.
- [`vendor-connectors-own-sections`](architecture/vendor-connectors-own-sections.md) — HARD RULE. Vendor connector sections (Holded, MailerLite, GoogleIntegration) are never merged into their consumer sections — vendors can be swapped; never re-export a vendor's wire DTO.
- [`orchestrator-marker`](architecture/orchestrator-marker.md) — An Orchestrator coordinates ≥2 sections, owns no tables or a repository. `IOrchestrator` is a sibling of `IApplicationService`, never a child — a table owner is a Section.
- [`crosscut-purity`](architecture/crosscut-purity.md) — A Crosscut (Audit, Email, Notification, Metrics) never calls into a section; when it needs cross-lane data, an Orchestrator gathers it and calls the crosscut with the data.
- [`governance-scope`](architecture/governance-scope.md) — Governance owns only Colaborador/Asociado applications, Board voting on them, and binding assembly votes. Don't file a feature under Governance because the Board uses it — audience isn't ownership.
- [`shared-drives-only`](architecture/shared-drives-only.md) — All Google Drive resources live on Shared Drives — API calls need `SupportsAllDrives = true` + `permissionDetails`; inherited access is preserved when managing direct grants.
- [`slug-routes-fallback-to-guid`](architecture/slug-routes-fallback-to-guid.md) — A slug-keyed URL must also accept the entity GUID in the same slot, looking up by Id when the slug doesn't match — new routes only; existing ones migrate opportunistically.
- [`user-profile-foundational`](architecture/user-profile-foundational.md) — UserService/ProfileService sit at the bottom of the stack — no outbound calls to Teams, Shifts, Tickets, etc. Only Crosscuts (Audit, Email, Notification, Metrics) are exempt.

- [`users-profiles-one-section`](architecture/users-profiles-one-section.md) — HARD RULE. Users, Profiles, and UserEmail are one ownership section (Humans); don't move code between Users/Profile just to satisfy a section-boundary rule.

- [`email-mutation-paths`](architecture/email-mutation-paths.md) — HARD RULE. `UserEmail.Email` is written only by the OAuth-callback reconcile primitive (`(Provider, ProviderKey)` match); `User.Email` is vestigial, never written by app code.

- [`no-identity-email-column-reads`](architecture/no-identity-email-column-reads.md) — HARD RULE. Application/Web code must not read `User.Email`/`NormalizedEmail`/`UserName`/`NormalizedUserName` — use `UserInfo.Email`/`IUserEmailService`. Enforced by HUM0019.

## code/

- [`admin-role-superset`](code/admin-role-superset.md) — When writing role checks/lists, include Admin (system-wide) and the domain's *Admin role (TeamsAdmin/CampAdmin/TicketAdmin) — never one without the other.
- [`always-log-problems`](code/always-log-problems.md) — When logging an expected/user-driven failure, use LogWarning and drop the exception object — LogInformation is invisible in prod.
- [`authorization-conventions`](code/authorization-conventions.md) — Controllers/routes use `[Authorize(Policy = PolicyNames.X)]`; views use `authorize-policy` or `IAuthorizationService`. Never `[Authorize(Roles=...)]` or `User.IsInRole` chains.
- [`auth-in-views-self-resolving`](code/auth-in-views-self-resolving.md) — In reusable views/components, resolve auth via injected `IAuthorizationService` in the template — don't pass `Can…` auth booleans on the view model.
- [`audit-pii-subject-allowed`](code/audit-pii-subject-allowed.md) — An audit entry may show PII unmasked only when the PII belongs to that entry's own subject.
- [`controller-base-conventions`](code/controller-base-conventions.md) — MVC controllers extend `HumansControllerBase`; API controllers extend `ApiControllerBase` — never direct `_userManager.GetUserAsync` or `TempData[...]` calls.
- [`comments-stay-short`](code/comments-stay-short.md) — Code comments and doc blocks get 1-3 lines stating what's true now and why — never a history of the decision.
- [`clamp-page-size`](code/clamp-page-size.md) — Use `ClampPageSize()` for page-size clamping instead of scattering inline `Math.Clamp(pageSize, ...)` calls.
- [`csv-use-csvhelper`](code/csv-use-csvhelper.md) — ALL CSV reads/writes go through CsvHelper via the shared `HumansCsv` config — never hand-rolled splitting/quoting/escaping or `string.Split(',')`.
- [`guard-tests-assert-the-message`](code/guard-tests-assert-the-message.md) — A test pinning a guard clause must assert its message or use an input no sibling path can reach — a type-only `Assert.Throws` still passes with the guard deleted.
- [`hangfire-method-signature-stable`](code/hangfire-method-signature-stable.md) — Methods called via `backgroundJobs.Enqueue<I>()`/`.Schedule<I>()` need a frozen signature — pin the call site to a no-defaults overload; never add/reorder/change its params.
- [`culture-and-language`](code/culture-and-language.md) — Use `CultureCatalog`/`CultureCodeExtensions` for culture lists, ordering, and display labels — no per-view language dictionaries.
- [`datetime-display-formatting`](code/datetime-display-formatting.md) — Render dates via `DateFormattingExtensions` — `ToDate`/`ToWeekdayDayMonth` etc. for display, `ToInvariantDate`/`ToIso8601` for machine. Never inline format strings (HUM0030).
- [`iban-mask-in-logs`](code/iban-mask-in-logs.md) — All IBAN output to logs/audit/errors must go through `IbanFormatter.Mask`.
- [`icons-fa6-only`](code/icons-fa6-only.md) — Use `fa-solid fa-*` (or `fa-regular`/`fa-brands`). Never `bi bi-*` — Bootstrap Icons aren't loaded and render invisibly.
- [`isgoogle-user-controlled`](code/isgoogle-user-controlled.md) — `UserEmail.IsGoogle` is user-set — never auto-set it in merges/syncs/dedup; the sanctioned auto-pick only runs when adding a brand-new row.
- [`img-alt-is-a-user-facing-string`](code/img-alt-is-a-user-facing-string.md) — An `<img alt>` on a member-facing view needs resx keys in all six cultures — the admin exemption doesn't cover an ungated modal opened from an admin page.
- [`json-serialization`](code/json-serialization.md) — System.Text.Json: `[JsonInclude]` on private setters, `[JsonConstructor]` on new classes/records, `[JsonPolymorphic]`+`[JsonDerivedType]` on polymorphic types.
- [`localization-admin-exempt`](code/localization-admin-exempt.md) — Admin/operator-only pages (`/Admin/*`, `/TeamAdmin/*`, `/Shifts/Dashboard`, `/Monitor/*`) don't need new resx keys — a page without that gate is never exempt.
- [`log-file-debugging`](code/log-file-debugging.md) — When debugging runtime errors, grep the log file first — don't speculate. Write diagnostic logs with entity IDs and actual values, not just "operation failed".
- [`lsp-integration`](code/lsp-integration.md) — After editing a `.cs` file, re-Read it — the `csharp-ls` LSP fires diagnostics on Read, not Edit.
- [`namespace-alias-application`](code/namespace-alias-application.md) — Referencing `Humans.Domain.Entities.Application`? Alias it `using MemberApplication = ...;` — it collides with the framework `Application` type.
- [`narrow-admin-role-needs-anyadminrole`](code/narrow-admin-role-needs-anyadminrole.md) — A new narrow admin-shell role (e.g. `CantinaAdmin`) must join the `AnyAdminRole` policy too, or holders pass their page but never see the ADMIN nav link.
- [`no-enum-compare-in-ef`](code/no-enum-compare-in-ef.md) — Enums with `HasConversion<string>()` compare lexicographically in SQL — never use `>`/`>=`/`<`/`<=` in EF queries; use `Contains()` with explicit allowed-values lists.
- [`no-extensions-for-owned-classes`](code/no-extensions-for-owned-classes.md) — Don't write extension methods for types this repo owns — add the method/property directly on the class. Extensions are only for BCL/third-party types.
- [`no-hallucinated-content`](code/no-hallucinated-content.md) — Never invent user-facing copy (benefits, policies, pricing) and hardcode it — wire to an admin-editable field or ask for the source text.
- [`no-hostile-api-design`](code/no-hostile-api-design.md) — Never propose deliberately awkward/ugly method names to discourage callers — restrict access via visibility and call-site pinning, not the name.
- [`no-magic-strings`](code/no-magic-strings.md) — When a string literal refers to a code identifier (property, method, role, entity type), use `nameof()`/a constant/enum instead — never a magic string.
- [`no-new-displayname-fields`](code/no-new-displayname-fields.md) — HARD RULE. Never coin a new `DisplayName`/`*DisplayName` field/property/parameter — pick a concept-specific name (`BurnerName`, `LegalName`, `GroupName`, `TeamName`, `Title`).
- [`no-paving-obsolete-fields`](code/no-paving-obsolete-fields.md) — When migrating a read/write, switch to the canonical replacement — never carry an `[Obsolete]` field/predicate into new code (e.g. `Profile.IsSuspended` → `State`).
- [`no-recomputing-a-pure-function-in-a-view`](code/no-recomputing-a-pure-function-in-a-view.md) — A `.cshtml` that re-derives a value a service/domain function already computed is a latent bug — carry the computed value through the DTO instead.
- [`no-remove-unused-properties`](code/no-remove-unused-properties.md) — Don't remove a seemingly-unused property/method without checking for reflection use — serialization, EF change tracking, cloning/merging, dynamic binding.
- [`no-rename-serialized-fields`](code/no-rename-serialized-fields.md) — Never rename a property on a JSON-serialized class — existing stored JSON expects the current property names.
- [`type-name-as-persisted-string`](code/type-name-as-persisted-string.md) — Before renaming a type, grep for `nameof(T)` written to a DB column and `Enum_{TypeName}_*` resx keys — pin the persisted one as a const, rename the resx keys with the type.
- [`no-system-subfolder`](code/no-system-subfolder.md) — Never create a `System/` subfolder — it shadows the BCL `System` namespace and breaks `System.X` refs in sibling folders. Use `SystemSettings/`/`Platform/`/`Infra/`.
- [`nodatime-for-dates`](code/nodatime-for-dates.md) — Use NodaTime types (`Instant`/`LocalDate`/`ZonedDateTime`), not `DateTime`/`DateOnly`/`TimeOnly` — server-side is ALWAYS UTC; convert to local only at display.
- [`nsubstitute-no-nested-substitute-factories`](code/nsubstitute-no-nested-substitute-factories.md) — Don't call a substitute-creating helper inline inside another `.Returns(...)` — NSubstitute can't tell which 'last call' it attaches to. Capture to a local first.
- [`prefer-base-class-for-cross-cutting`](code/prefer-base-class-for-cross-cutting.md) — Adding a cross-cutting concern (diagnostics, telemetry, lifecycle hooks) to ≥2 similar classes? Propose a shared base class first — an interface only if that can't work.
- [`prefer-setup-work-for-trivial-usage`](code/prefer-setup-work-for-trivial-usage.md) — Choosing heavier setup with trivial call sites vs. lighter setup with verbose call sites — prefer heavier setup; call sites multiply, the abstraction is written once.
- [`profiles-section-plural`](code/profiles-section-plural.md) — `Humans.*.Services.Profiles` (plural). Singular collides with the `Profile` entity.
- [`razor-script-src-at-escape`](code/razor-script-src-at-escape.md) — In `<script src>` URLs use `&#64;` for npm scopes (`@turf`, `@mapbox`) — `@@` gets mangled because `NonceTagHelper` claims every `<script>` tag.
- [`resource-key-prefix-matches-section`](code/resource-key-prefix-matches-section.md) — A new resx key is prefixed with its section's plural PascalCase name (`Users_`, `Tickets_`) — existing keys are not backfilled.
- [`resx-structure-aware-edits`](code/resx-structure-aware-edits.md) — Add/remove a `.resx` key by exact-match text replacement of the whole `<data>` block, once per culture — never `sed` or an XML round-trip; validate with a parser after.
- [`sanitized-markdown-rendering`](code/sanitized-markdown-rendering.md) — Use `@Html.SanitizedMarkdown(...)` in Razor — never inline `HtmlSanitizer`, `Markdig.Markdown.ToHtml`, or local `ConvertMarkdownToHtml(...)` helpers.
- [`search-endpoint-response-shape`](code/search-endpoint-response-shape.md) — Autocomplete/search JSON endpoints use stable typed records. Reuse shared mapping helpers across endpoints feeding the same client interaction.

---
name: Section contributions are discovered files, not Section.cs edits
description: Adding a nav link, admin tile, job, policy, health check, endpoint, or chrome/dashboard component for a section → an internal Section<Seam> class at the section root, never a method on Section.cs or an edit to a Shell composition class.
---

A section opts into Shell composition by adding an `internal sealed` stateless class implementing one of the `ISectionContribution`-derived seam interfaces in `Humans.Base.Interfaces` (`ISectionNav`, `ISectionAdminNav`, `ISectionAdminTiles`, `ISectionChrome`, `ISectionMemberDashboard`, `ISectionThingsToDo`, `ISectionJobs`, `ISectionHealthChecks`, `ISectionEndpoints`, `ISectionPolicies`) — one file per seam, at the section project's root, named `Section<Seam>` (`internal sealed class SectionNav : ISectionNav`, `internal sealed class SectionJobs : ISectionJobs`, …), with a parameterless constructor. `Section.Register` never grows a method for this; it stays the DI-registration entry point only.

**Why:** `SectionDiscoveryExtensions.RegisterContributions` finds every `ISectionContribution` implementation by the same dependency-graph walk `ISection` uses (via `DiscoverImplementations<T>()`, which walks `GetTypes()` rather than `GetExportedTypes()`), and registers it as a singleton against every seam interface it implements. A new seam interface deriving from the marker costs Shell no edit; a method bolted onto `Section.cs`, or a by-name edit to a Shell composition class, isn't discovered by anything and just reopens the compile-time coupling nobodies-collective/Humans#1073 removes. The `Section` prefix on the class name isn't decoration: a bare `Jobs` class collides with the section's own `Jobs` namespace — `class Jobs` in `Humans.Consent` is CS0101 against `Humans.Consent.Jobs`, and a `Jobs()` method inside it is CS0542 on top — the prefix removes that whole class of collision. **Internal, not public:** Shell finds a contribution by reflection and no other section ever names it, so it is not part of the section's public surface (`Contracts/`) — a public contribution class would trip HUM0034 (a section's types are internal outside `Contracts/`), and discovery being reflection-only against `GetTypes()` is what keeps it out of that rule without needing an analyzer carve-out.

**How to apply:** need a section to show up in the admin sidebar, member top nav, a dashboard tile, a recurring job, a health check, an authorization policy, or a layout/dashboard chrome slot → add `internal sealed class SectionNav : ISectionNav`, `internal sealed class SectionJobs : ISectionJobs`, etc. at `src/Sections/Humans.<Section>/`. Never edit Shell's composition classes (`AdminNavComposition`, `SectionNavViewComponent`, `ChromeSlotViewComponent`, `RecurringJobExtensions`, `AuthorizationPolicyExtensions`, `Program.cs`) to name a section directly — that defeats the seam and blocks future section optionality (capstone lane #1081). See [`design-rules.md` §8b](../../docs/architecture/design-rules.md#8b-cross-section-fanout--contributor-pattern) for the seam catalog and composition/ordering rules.

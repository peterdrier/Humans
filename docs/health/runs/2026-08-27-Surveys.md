## Assessment summary

Surveys is a well-built section carrying a lot of correct, hard-won privacy machinery and a
surprising amount of prose that describes a codebase from three months ago. Its target shape
([`health.md`](../../../src/Sections/Humans.Surveys/Docs/health.md), written before any scan)
holds up: one service, one repository, controllers split by audience, one page flow. Nothing about
the structure needs changing.

What it does have is real defects on the invited answering path — findings 1, 2 and 3 —
all of which come from the same place: `Invitation.Completed` is used as a submit guard inside a
*resolve* method, and everything downstream of a spent token inherits that. Finding 1 is the one
that shows: the survey's authored thank-you text has never been shown to the two tiers that
matter.

The rest is prose drift. The section's invariant doc names a controller that does not exist,
carries a `wheat:` marker pointing at a deleted plan file, and states one of its Negative Access
Rules as a double negative that reverses its meaning. Comments across the section still narrate a
phased build-out ("send/submit/results/export/GDPR are added in their phases") that finished long
ago, and a `Contracts/` → `Jobs/` move that is two moves stale. Orphaned XML doc comments on
`ISurveyService` describe members that are no longer there.

Notably absent: any structural finding. The single largest reforge item (`largeClass`
`SurveyService`, 65 pts) is deliberately **not** a finding — the target says one service over one
aggregate is correct, because splitting it puts the anonymity contract in two places.

## Worked

Findings 1–12:

- `doctor(surveys): restore the authored thank-you copy on the invited path` — findings 1, 4–12.
  The submit redirect now leaves `SurveyCompletion(SurveyId, Culture)` in the session under a
  `survey-thankyou:…` key, which the thank-you page reads; a link opened without a marker falls
  back to resolving the token/slug as before.
- `doctor(surveys): don't remind about a survey nobody can answer, and stop 500ing on a bare
  /Survey/Answer` — findings 2 and 3.

Finding 13 was worked after Peter answered it: a page whose questions are all hidden — the state a
survey with no questions at all is always in — now renders `Closed` with `Reason = "empty"`
("There is nothing to answer") instead of redirecting to thank-you. Nothing was submitted, so no
completion marker is written and the session is left alone. Peter's reasoning: the bigger bug is a
survey with no questions, and reporting it as completed hides it; saying "nothing to answer" puts
the real problem in front of someone who can fix it.

**Deliberately not done for finding 1:** carrying the survey id as a route value. It is less code,
but it turns two `[AllowAnonymous]` GETs into an ungated by-id lookup of any survey's authored
title and closing text, at any status, bypassing the `AllowAnonymous` and window gates that
`ResolvePublicContextAsync` enforces. The session marker keeps it server-side and carries the
answered culture for free. Adding a method to `ISurveyService` was not an option (interface
additions are skip-and-queue).

Surfaces hit: **localization** — finding 13 adds `Survey_NothingToAnswer_Heading` and
`Survey_NothingToAnswer_Body` to all six culture resx files; findings 1–12 add none (the thank-you
copy is author-supplied per culture, and `Survey_ThankYouFallback` is unchanged). **Authorization** — no
change; finding 1's design was chosen specifically to avoid widening the anonymous surface, and
finding 3 narrows a crash to a clean invalid-link path. **Audit** — unchanged; the reminder sweep
still logs one `SurveyReminderSent` entry per run. **GDPR** — untouched. **Invariant doc** —
`Surveys.md` updated in the same commits for both behaviour changes. **Migrations** — none.
**Navigation** — unchanged. **Tests** — new coverage in `tests/Humans.Surveys.Tests` for the
completion marker, the answered culture, the cross-slug deny path, the missing-token guard and the
reminder answer-window, and the nothing-to-answer page (185 passing, up from 176).

## Retro

**The selector picked a section it had just printed as blocked** (finding 15). This is the most
serious thing the run found and it is in the skill, not the section. I did not edit the script
(skill files are Peter's); I normalised the case in my own hand-built `prs.json` and re-ran, which
gave Surveys. Cost: one wasted selector round.

**My first fix for finding 1 was wrong and a second opinion caught it.** I passed the survey id as
a route value on the thank-you redirect, reasoning that a Guid is unguessable. The reviewer pointed
out that (a) survey ids already appear in image URLs on the answer page, so they are not secret to
respondents, (b) `id` and `t`/`slug` were never cross-checked, so any slug could render any
survey's copy, (c) it bypassed the `AllowAnonymous` and status gates that the by-slug resolve
enforces, and (d) it left the *culture* half of the same defect unfixed. The session-marker design
it proposed instead is smaller, keeps the id server-side, and fixes the culture. **The reviewer also
caught that my tests would all still pass if the redirect were reverted** — they pinned the
thank-you action but nothing exercised the redirect that feeds it. That is the failure mode the
second opinion exists for, and it would have shipped without it.

**Wasted motion:** I wrote a shell-level claim that `MembershipRequiredFilter` did not exist while
the grep in the same call was returning hits for it, and nearly carried a false finding against a
`Surveys.md` line that is correct. Verifying it cost a round I should not have needed.

**What striking revealed:** the behaviour defects are one shape — `Invitation.Completed`
doing double duty as a submit guard inside a *resolve* method, so every consumer of that resolve
inherits a gate meant for one caller. The thank-you page is the consumer that shows it. That is
worth naming in the target doc if a later run touches this path again.

**Target diff:** none. `health.md`'s structure section describes the section as built, and nothing
struck this run moved it. The one addition worth making is that the completion marker is now part
of "one page flow" — recorded in `Surveys.md`'s invariants rather than the target, since it is a
mechanism, not a shape.

## Assessment summary

Cantina is a table-less read-side aggregator over `IShiftManagementServiceRead`,
`IBurnSettingsService` and `IUserServiceRead`, gated by `CantinaAdminOrAdmin`, with read-only
routes and no writes. It was doctored on 2026-08-22 and **its own code has not changed since**.

That is the whole story of this run. A section that owns no tables cannot notice when the
sections it reads change underneath it, and they did:

  gap Cantina's docs still described as open and told readers not to claim was fixed.

### The defect

`CantinaRosterService` stitched each row's display name from `ProfileInfo.BurnerName`. Since
nobodies-collective/Humans#1097 that field is one *input* to the resolution, not
the result: `UserInfo.BurnerName` carries
`User.BurnerName → Profile.BurnerName → legacy DisplayName`. Any human whose name only ever
landed on the user row rendered as `"(unknown)"` on the day matrix and in both CSV exports — the
sheets that get printed and carried into a kitchen.

The 2026-08-22 run looked at this same `"(unknown)"` string and ruled it not a defect. That
ruling was correct then and wrong now, which is the lesson in the retro.

Fixed by reading `UserInfo` once for the whole cohort and taking both halves of each row from it
(the resolved name, and the `Profile` that carries dietary fields), deleting the derived profile
map. Pinned by `GetDailyRoster_BurnerName_ComesFromTheResolvedUserName`, which fails before and
passes after.

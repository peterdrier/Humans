## Assessment summary

First doctoring of Backdoor (never-doctored tier, median surface-score pick). Target shape
written fresh to `Docs/health.md`.

Backdoor is a leaf: it owns one table (the API keys) and everything else it exposes is
translation over the contracts interfaces of the sections it serves. That shape is intact — no
controller here touches a foreign repository, and the auth model is genuinely enforced in one
filter. What the section carries instead is **narration about where its routes used to live**.
The consolidation that created it moved surfaces in from Debug, Agent, Issues, Feedback and
Surveys, and each move left a "was `/api/X` in section Y" clause behind, plus a run of copies of
one comment restating the line under it (findings 4, 5, 13).

The run's two real defects came out of the target rather than out of a scan (findings 1, 3):
deriving the shape first is what made them findable, and neither would have surfaced from
reading the code for smells. That is the argument for Phase 3c earning its cost on a section
this small.

The section's test project was strong where the section's own logic lives and absent where it
translates, which is the wrong way round for a section whose whole promise is attribution
(finding 9). Closed.

The headline was finding 18 — a business-behavior question no document answered, so the run
pinned the current behavior rather than picking a side. Peter ruled it a bug; it and the other
two code rulings are applied here (findings 41–43).

41. **The patch pipeline, unblocked (finding 14, ruling: normalise).** With the error bodies free
    to converge, the blocker in finding 14 dissolves: what made a shared helper a parameter bag

    something shared:
    collapse within a controller, not across them.
42. **The admin-grade issue queue, fixed (finding 18, ruling: a bug).** The scoping arguments were
    hardcoded at the call site (`viewerUserId: Guid.Empty, viewerRoles: [], viewerIsAdmin: true`)

    `NameIdentifier` claim and no roles. The fix is at the gate rather than the call site: the
    filter now resolves the owner's active role assignments through `IRoleAssignmentService` and
    installs them as `ClaimTypes.Role` claims, so `User.IsInRole` and `User.FindAll` behave
    exactly as they do for a cookie-authed request and every surface under the filter is
    role-aware at once. `BackdoorIssuesController.List` reads its three arguments off the

    already referenced. The pinning test from finding 18 is inverted: a Board-only key now reads
    the Board-only queue. The §5 Seams entry that recorded the open question is retired.

    `IsUserAdminAsync`/`IsUserBoardMemberAsync` for eligibility, and the filter then calls

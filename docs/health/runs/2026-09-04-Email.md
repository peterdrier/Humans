## Findings

Numbered once. Later blocks cite the number, never a position.

1. **Resource keys nothing renders.** The neutral `EmailResource.resx`
   and its five culture files each carried the two heading keys the branded body
   composer stopped using and the ten `Email_BoardDigest*` /
   `Email_BoardDailyDigest*` keys left behind when `SendBoardDailyDigestJob` was
   retired. *Struck.*

2. **Caller-supplied markdown reached two email bodies unsanitized.**
   `EmailRenderer.RenderFeedbackResponse` and `RenderIssueComment` called
   `Markdig.Markdown.ToHtml` directly, which passes raw HTML in the source
   straight through — while `RenderSurveyInvitation`, three lines up, already
   routed its caller-supplied copy through `SanitizedMarkdownRenderer`. A staff
   reply to a feedback report and an issue comment are both human-authored, so a
   `<script>` tag or an event-handler attribute written into either reached the
   body verbatim. This is the invariant in `Docs/health.md` §4 — "every value
   interpolated into an email body is either HTML-encoded or passed through the
   canonical sanitizing markdown renderer" — and these two call sites broke it.
   *Struck, with tests that fail against the old calls.*

   `RenderCampaignCode` also renders raw, and is deliberately left alone: a
   campaign's `EmailBodyTemplate` is `AdminOnly`-authored copy, not a member's
   words, and an admin who can write it can already send the mail. Sanitizing it
   would strip HTML and images an admin wrote on purpose, which is a behaviour
   change. Whether admin-authored campaign copy should be trusted with raw HTML
   is **queued for Peter**; `Docs/health.md` §4 now records the carve-out instead
   of reading as absolute.

3. **`ShiftSignupId` is a column with no reader.** The schema carries the column
   and a filtered `(ShiftSignupId, TemplateName)` index for "one email of each
   template per signup". Nothing writes the column and nothing queries the index;
   `Docs/Email.md` asserted twice that a dedup query "filters on the column
   directly". The doc is corrected here. Removing the column and its index is a
   schema change, so it is **queued for Peter**, not done.

4. **`TriggerImmediate` and `TimeSensitiveTemplates` have already drifted.**
   `Docs/Email.md` claimed "the same list drives `TriggerImmediate` on enqueue,
   so the two behaviours cannot drift." They are separate switches:
   `EmailMessageFactory.EventLifecycle` sets `TriggerImmediate: true` on a
   template that is not in `TimeSensitiveTemplates.Names`, so an event-lifecycle
   message forces an immediate drain but is *not* ordered ahead of bulk mail once
   that drain runs. The doc is corrected to describe what happens. Which of the
   two lists is wrong is a behaviour question — **queued for Peter**.

5. **Some templates are hardcoded English.** A run of `EmailRenderer` methods near
   the end of the file build their bodies from string literals rather than
   `EmailResource`, so those recipients get English whatever their culture. `Docs/health.md` §3 records
   this as the shape the code does not yet have. Fixing it means inventing new keys of copy in
   all six languages, which is a content decision, not a refactor — **queued for
   Peter**.

6. **The section's `design §N` citations resolved to the wrong document.** `AGENTS.md`
   calls `docs/architecture/design-rules.md` "the regulations", so a reader
   follows "design §15 step 6b" there and lands on the Section Caching Pattern;
   "design §5" lands on Decorator Caching. Every one of them meant the G5
   playbook (`docs/sections/G5-SECTION-TEMPLATE.md`), whose `step 6b` and
   `lane 5b-1` are the real referents, or meant nothing at all. *Struck.*

7. **Dead project names throughout the section's prose.** Both `.csproj`
   headers, `Docs/data-access.md`, `EmailResource.cs` and `_ViewImports.cshtml`
   described `Humans.Application`, `Humans.Infrastructure`, `Humans.Interfaces`,
   `Humans.Domain`, a `Humans.SystemSettings` section and an
   `ISystemSettingsService`. None exist; the pause flag is `ISettingsService` /
   `SettingKeys` and `<vc:human>` lives in `Humans.Base`. The Contracts csproj
   header was a migration diary; it keeps the facts a reader needs — why the leaf
   project exists and what it may reference — and its consumer and acyclicity
   claims were re-verified against the actual `ProjectReference` items.
   *Struck.*

8. **Derived counts and a false test claim in `Docs/Email.md`.** "the 71
   `Email_*` keys" (a count, wrong the moment the set changes — and wrong now);
   "Profiles:" heading the `IUserEmailService` dependency when there is no
   Profiles section and Users owns that contract; and the architecture test
   credited with pinning the one-method `IEmailService` surface and the
   localization route, which it does not — it pins the constructor shape, the
   absent Hangfire dependency, and the connector sides. *Struck.*

9. **A cancelled drain is safe only by accident — withdrawn as a defect.** The
   throttle `Task.Delay(1000, cancellationToken)` runs *after* `MarkSentAsync`,
   so a shutdown lands on a row already marked `Sent` and falls into the general
   `catch (Exception)`, which calls `MarkFailedAsync`. That looked like a defect:
   a sent message recorded `Failed`, with `Failed` mirrored onto its campaign
   grant. It is not, because `MarkFailedAsync` opens its own context with the
   same cancelled token and throws before writing anything — the failure path
   dies before it can do the damage. A guard and a pinning test were written and
   **reverted** when the test passed against unguarded code too. Recorded here
   rather than struck: the correct outcome rests on EF throwing on a cancelled
   token, not on anything the section states.

10. **The real cancellation exposure is upstream of that.** If a transport
    hands the message to the SMTP server and *then* observes cancellation,
    `MarkSentAsync` throws on the cancelled token, the row stays unsent, and the
    5-minute stale window re-picks it — a second delivery of a message that was
    already accepted. That contradicts `Docs/health.md` §4's "a message that
    succeeds is never sent twice". No surgical fix exists: it needs either a
    `Sending` status or an idempotency key, both schema changes, or an explicit
    decision that at-least-once is the accepted contract. **Queued for Peter.**

11. **A top-level `Health/` folder is outside the allowed layout.** The
    `section-file-layout` rule's ALLOWED set does not include `Health/`, and these
    sections have one: Agent, Email, GoogleIntegration, Guide, Tickets. Not
    Email-specific, so it goes to the sweep queue as central debt rather than
    being fixed in one section here.

12. **`Humans.Monitor/Docs/data-access.md` still names `ISystemSettingsService`
    and `SystemSettingsDbContext`.** Found while sweeping finding 7's corrected
    strings repo-wide. Off-section — sweep queue.

13. **`email-flag-violations-remediation.md` sits in Email's `Docs/features/`
    but asserts only Users and GoogleIntegration behaviour.** It documents no
    Email invariant. Moving it is another section's call — **queued for Peter**.

## Retro

**What did the selector get wrong?** Nothing this run. Email sat at the median
of the never-doctored tier on a clean reforge score, and the pick held up: a
2830-LOC section with a real security finding and a doc set that had drifted
from projects that no longer exist is exactly what the tier is for.

**What was the most expensive mistake?** Computing "dead keys" with
`git grep` and no pathspec, so the pattern matched the `.resx` files themselves
and reported zero dead keys — contradicting the Prose thread, which was right.
Restricting the search to `*.cs`, `*.cshtml`, `*.razor` gave the real answer.
The second-most expensive was writing a guard and a pinning test for finding 9
before checking that the test failed against unguarded code. It did not.

**What would have caught it sooner?** For both: run the candidate fix's test
against the *unfixed* file before writing the fix's commit message. That is what
turned finding 9 from a strike into a withdrawal, and it is cheap — one `git
stash push` of the one file.

**What should change in the skill?** Phase 4 already gates non-mechanical
strikes behind `doctor-reviewer`, and that gate paid for itself twice this run:
it caught the resx reformat, and its reachability sweep was more thorough than
mine. Nothing to propose beyond the Phase 0 prompt edit above.

## Retro

The run's worst hour went to a build that was never broken. Mid-strike, `dotnet build` started
reporting Razor errors in `EmailOutbox.cshtml` — a file nothing had touched — with columns a few
characters off and identifiers sliced mid-word. It reproduced from a clean `obj/`, and with every
working-tree change stashed, which is exactly what a branch that broke the build looks like. It was
the compiler server: a dispatched reviewer agent was running `dotnet test` while the main thread
built, and `memory/process/no-concurrent-roslyn.md` describes that symptom and its cure precisely.
The atom existed; the run did not read it until after diagnosing the same thing from scratch. The
lesson is not a new rule but a sequencing one: a thread that dispatches an agent which builds must
not build alongside it, and the INDEX scan belongs *before* the diagnosis, not after.

The reviewer gate earned its cost twice, and both times on the same failure mode: a test that
passes without pinning anything. Once on my rewrite of the failed-backfill test, which asserted a
literal against an input containing no failure signal, and once on the first draft of the
grant-mirror test. Both would have shipped as coverage while pinning nothing.

Process note: the run repeatedly piped `dotnet` output through `grep` and `tail`, which
`memory/process/dotnet-verbosity-quiet.md` forbids for exactly the reason it names — a failure's
details live above the summary. It cost nothing here because nothing failed, which is the only
reason it went unnoticed.

The section itself is in good order. Nearly every finding traces to one of three recent PRs, which
is what a section looks like when it is being maintained rather than neglected: the code moved and
the prose lagged by a few weeks.

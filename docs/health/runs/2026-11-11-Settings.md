## Assessment summary

Settings grew a second job since the last run: it is now the register of every event cycle,
not just the current one — an event list with make-active, "create next event", a global
timezone, and a no-overlap rule between cycles. The code that came with that is in good shape:
one service, one repository, refusals as results, every admin write audited and every write
that may have changed a cycle announced to the listening sections.

The drift is in the prose around it. The invariant doc said there was no fan-out and that only
the save was audited; its own invariants list carried appended notes (one of them a form
placeholder), and the target shape still described a contracts project the section folded into
a folder weeks ago. The event form also re-checked two rules the save already owns, a leftover
from when a failed save re-rendered the form with field-level messages.

One member-visible defect: the read-only Events tab rendered an inverted strike range when an
event has no strike days.

Independence check: pass. Findings 1, 2 and 10 come from the target and a walk through the
read-only rendering, not from a tool, score or grep; finding 2 is a spec-versus-reality delta
(the form's "field-level message" reason no longer exists).

## Assessment summary

First doctor pass over Settings, a young, small, deliberately transitional section
(reforge 116 @ 0.29.0, loc=1096, cogP95=6, cogMax=10): the `system_settings` key/value
store plus `settings_event`, the staged new home of the app-wide event values
(nobodies-collective/Humans#1104). The target shape
([`health.md`](../../../src/Sections/Humans.Settings/Docs/health.md), written this run
before any scan) finds the structure right as built: one service registered under two
interfaces, one repository, a carry orchestrator, two admin screens. The duplication
against Shifts **is** the migration and is not a defect.

No behavior bugs. What the section had instead: it shipped without its per-section
invariant doc (finding 1 — a conformance hit standing since 2026-08-18), a dead
project reference from GoogleIntegration left behind by the Monitor carve-out
(finding 2), and comment/doc drift of one recognizable kind — text written for the
nobodies-collective/Humans#1104 review that narrates the fixed bug, the internal PR labels, and callers that do
not exist yet, instead of the code as it stands (findings 3–9). Four small test gaps
(findings 10–13) rounded out the strikes.

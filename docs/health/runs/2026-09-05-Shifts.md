## Assessment summary

First doctor pass over Shifts, the largest section in the tree: the rota/shift/signup
state machine, the coordinator dashboard and its analytics, volunteer tracking, event
settings, the volunteer's own shift profile and iCal feed, plus a Contracts leaf that
Teams, Users, Onboarding, Camps, Gate, Search, EarlyEntry and Debug all read. The target
shape ([`health.md`](../../../src/Sections/Humans.Shifts/Docs/health.md), written this
run before any scan) finds the structure right where it is load-bearing — one repository
contract, one signup state machine, one cached per-user projection — and names two seams
it would move: the analytics half of `ShiftManagementService` (finding N7) and a leaf
that exposes members nothing outside the section calls (finding N11).

One authorization gap (finding 1): a department coordinator could delete any team's rota
or shift by id, because the two delete actions skipped the team-scope check every sibling
action performs. Fixed with a red-then-green controller test. Two smaller behavior gaps
(findings 12, 13) and a silent no-op (finding 14) fixed alongside.

The rest was drift: the invariant doc named a service that does not exist, a route that
moved to EarlyEntry, and Teams-contract members that were never there (finding 2); the
code comments narrated the G5 move, the fixed bugs and the PR numbers that produced them
rather than the code as it stands (findings 6, 7); and a handful of member-facing strings
were hardcoded English on pages the section otherwise localizes in six cultures
(finding 8). Three members and a repository test had no caller (finding 17).

deadline was the wrong shape for a section this size: the History thread (50 findings)

leaf-trim list (N11) is concrete rather than a hunch.

**Wasted motion:** the BRIEF told every thread the read interface had eleven members
(N10); a false dead-code claim from the Prose thread cost a verification round (N14); a
build ran while the Shape thread held reforge and produced phantom Razor errors that took a
clean, a re-build and a build-server shutdown to clear (N13); and the comment-cut batches
went to the reviewer after committing rather than before, so the eight rejects became a
fourth commit instead of a smaller diff (N15).

**What the assessment missed that striking revealed:** the reviewer's eight points were
all visible in the diff and none of the assessment threads would have caught them — they
are rewrite errors, not assessment errors. Two rewrites asserted facts that were never
true (a leaf with no project reference; a `SurfaceBudget` attribute), which is the same
failure the Cantina run recorded: "when a doc explains why an unused member exists, check
that the explanation is true before writing it."

**Target diff:** none possible — first doctor pass; `health.md` was written this run.

re-read of Phases 5–7 was applied after the last.

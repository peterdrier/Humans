**What the selector/rubric got wrong:** nothing. Tour was the last never-doctored section; it is
unscored by reforge, so the selector ranked it by warning rather than by score
(peterdrier/Humans#1601 already records this). The section was far under budget for a first
pass, which is what a content-only section should be.

**Wasted motion:** one suspected bug that was not one. The inline `tour-js` script carries no
literal nonce, and the app's CSP has no `unsafe-inline`; proving `NonceTagHelper` reaches it
through `@addTagHelper *, Humans.Base` meant emitting the Razor generated code. Worth it once —
it is now the first item of load-bearing weirdness in `health.md` — but the Freshness thread's
mechanism claim for finding 3 (that Shell's `_ViewStart` does not apply to section RCLs) was
wrong and cost a second check: Teams has no `_ViewStart` and renders in Shell chrome.

**What the assessment missed that striking revealed:** the first comment cut added a word
("the **only** way back") that the page's own `/About` links falsify, kept a project name
(`Humans.Infrastructure`) that no longer exists, backdated a replacement example to a view
that was not a section view when the comment was written, typed a count into a doc whose own
marker forbids it, and overstated what `EndpointAuthorizationTests` pins. Five defects in a
"mostly mechanical" batch, all caught by the reviewer gate. The assessment also named a CI test
(`SectionControllerDiscoveryTests`) that does not exist; Phase 5 read `tests/` before writing
finding 12 into `health.md`.

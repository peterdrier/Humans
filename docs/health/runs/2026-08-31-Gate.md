## Assessment summary

Gate is a young, deliberately-shaped section whose *code* is right and whose *words* are not:
the shared-supervisor-PIN override design shipped (peterdrier#1079) over the retired
per-supervisor-PIN flow (bypassed by peterdrier#1075), and a wide band of comments, XML docs,
section docs and even user-facing admin copy still described the retired design — some of it
asserting security properties that are the opposite of what the code does ("no PIN" on the
override panel; "supervisors can't self-enrol"). The run was therefore mostly doc-truth
restoration, plus small dead-client-remnant deletions, a Set<T>() normalization, an enqueue-DI
collapse, and test pins for the section's untested invariants (GDPR erasure asymmetry, merge
re-point + PIN carry-over, retention disable, per-action deny policies, throttle window). The
big deletion — the whole unreachable claim-flow subsystem incl. the `gate_staff_pins` schema —
is Peter's ruling (nobodies-collective/Humans#933) and was not touched. No reachable-path
functional bug was found.

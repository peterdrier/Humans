## Assessment summary

Surveys was last seen on 2026-09-07 (peterdrier/Humans#1618). Since then the Workgroups §11
self-service change landed a whole new lane: any approved-profile Human can author a survey,
and a Board approval queue stands between authoring and sending. The code shipped; the prose
did not follow it. Nine of this run's seventeen findings are a doc, a comment or a debt row
still describing the pre-§11 world where only the Board could author.

The approval state machine itself was walked by hand — every controller action, every
`SurveyOperationRequirement`, the handler's author/Board split — and no authorization hole was
found. The drift is entirely in what the section *says* about itself, plus one markup bug
(reject modals emitted inside `<tbody>`) and one partial abstraction (`SurveyDetail`'s
author id defaulting to `Guid.Empty`, the exact value the handler denies to everyone).

The 3c target shape was rewritten around the new lane: it now carries an **Approve** row, two
structure lines ("Authoring is open, sending is not"; "A resource handler holds the per-survey
rules, the service holds the same rules again"), and a `file:line` enforcement cite on every
invariant — which the 2026-09-07 target lacked. That target is what made P1 and P2 legible:
authoring is open, but the only navigation to `/Survey/Admin` is `BoardOrAdmin`-gated, and
every preview action is Board-only, so an author can reach neither the page nor a rehearsal of
their own survey. Both change visibility or authorization, so both go to Peter rather than
becoming strikes.

## Retro

What worked: rewriting the 3c target *before* reading any thread output. The 2026-09-07 target
was not wrong — the section moved under it — but it carried no enforcement cites, so nothing in
it could be checked against a line of code. Adding a `file:line` to every invariant turned the
target from a description into a test, and that is what surfaced P1 and P2.

What to keep: three threads (History, Inbox, Prose) independently hit the same localization
debt row and narrowed it three different ways. The union was better-scoped than any single
thread's version. Overlapping lenses on the same artifact are not waste.

What cost time: a scripted rewrite of this run file's narrative blocks clobbered the File
coverage table and had to be rebuilt from the inventory. Structured sections of the run file
should be filled by a line-oriented pass, never by a whole-file string replace.

What cost most: the enforcement cites were written in Phase 3c against the tree as it stood then,
and every later strike that touched `SurveyService.cs` shifted them. Round 5 found seventeen of
them landing on a blank line, a brace, or the statement next door — an invariant pinned to nothing.
The gate that would have caught it does not exist: `doctor.py trace` resolves a `file:line` name to
a file, never a line to the claim it is supposed to enforce. A target shape whose cites are
unchecked is a target shape that rots between the phase that writes it and the commit that ships
it. Re-resolve every cite as the last act before the PR, or teach `trace` to print the cited line
so the resolution is eyeballable.

Skill issues to file: one — `doctor.py trace` verifies the path half of a `file:line` cite and
silently accepts any line number, including a line that does not exist. Filing it against
peterdrier/Humans as the routine directs.

   **Answered — "restrict it, shouldn't need close on an approve/reject state change." Applied:**

   exits; the two docs say so again.

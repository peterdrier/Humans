## Findings

1. `ExpenseReportAuthorizationHandler` grants a finance admin `Endorse` and `CoordinatorReject` on a
   Submitted claim, so the detail page offers them the endorse card; `CoordinatorEndorseAsync` and
   `CoordinatorRejectAsync` then refuse anyone who does not coordinate the category, and the admin
   gets "Endorsement failed". `FinanceAdmin_CanEndorse_SubmittedReport` pins the grant,
   `CoordinatorEndorseAsync_Throws_WhenNotCoordinator` pins the refusal, and `Expenses.md` says finance
   admins hold every coordinator capability. Repo-wide: `git grep -n RequireCoordinatorForCategoryAsync`
   hits `Services/ExpenseReportService.cs` only.
2. Member-facing Expenses pages render hardcoded English: `Edit.cshtml`, `LineEdit.cshtml`,
   `LineProofs.cshtml`, `NewLine.cshtml` and `NewLineChoice.cshtml` never use the localizer, and
   `Detail.cshtml`, `Iban.cshtml` and `New.cshtml` only in places. Filed as EXP-5.
3. `ApproveAsync` sends the approval email after the approval commits, uncaught; if the send or the
   submitter lookup throws, `ApproveWithResultAsync` reports "Approval failed" for an approval that
   stands and whose Holded push is already queued.
4. `IExpenseReportServiceRead` is the section's cross-section read interface and nothing outside the
   section reads it; the section's own controller is its only consumer
   (`memory/architecture/section-read-write-split.md`). Repo-wide: `git grep -n IExpenseReportServiceRead`
   finds no code outside `src/Sections/Humans.Expenses`; the other hits are docs and reforge snapshots.
5. `Expenses.md` drifted: the Review row claimed the admin shell for finance admins, the outbox job's
   registration was said to stay in Shell, the read interface's missing `[SurfaceBudget]` was blamed on
   a finished migration, and the cross-section call list left out Email and the Holded read interface.
6. The Edit page's `CanEditHeader` was written and never read, and its `CanEditLines` was always true —
   only the `Edit` grant reaches `PopulateEditModelAsync`, so the view's read-only branches were dead.
7. Submitting a claim that is no longer a Draft reports "Receipt lines need an attachment and your
   payment IBAN must be set" — both of those cases throw their own messages; the false return only
   means not found, not a Draft, or the repository refused.
8. `ExpenseReportService`'s class summary calls it an orchestrator; it owns the section's repository.
9. Decision-history comments: the travel-line removal block in `ExpensesController`, and test comments
   narrating what the job used to do and which page the queue replaced.
10. The coordinator-reject test was named for a return to Submitted while asserting Draft.
11. No test pins that a rejection leaves `MaxAmount` standing (a Peter-confirmed rule), nor that an
    approval for a member without a notification address skips the email.
12. The user guide never mentions the approval email.
13. Finance's expense-reimbursement process doc says one Holded document per receipt; it is one per
    bookable line, and legacy claims keep their single document.
14. `CENTRAL-47` cites `Humans.Expenses:46` for the "design §8" comment, which now sits at `Section.cs:52`.
15. Throwing and result-returning test pairs repeat one rule each; they fall with EXP-1, not before.
16. The dated design specs still describe SEPA and a Paid state; they are historical and carry banners.
17. The Edit page's "changing the category after submission requires a withdraw and re-file" hint was
    shown to a finance admin editing a submitted claim, whose category change the service accepts.
    Raised by the reviewer of finding 6.

## Assessment summary

First doctor pass over Scanner, the smallest scored section in the solution (reforge 15,
loc=197, cogP95=7, cogMax=7): two camera tools for ticket staff — a client-only barcode
decoder and a read-only ticket lookup that assembles a door-context card from seven
cross-section reads. The target shape
([`health.md`](../../../src/Sections/Humans.Scanner/Docs/health.md), written this run
before any scan) finds the structure right as built: one controller, one render model,
one partial, two pages over one camera module, no service layer, no cache. The one thing
the target would not build is the second half of the provide list, which rebuilds Events'
occurrence-to-feed-item rule by hand (finding 12, a seam).

No behavior bugs. What the section had instead was prose that outlived the Gate section
and the G5 project split: a landing-page string false in six languages (finding 1), an
authorization doc describing an action that never existed (2), a Contracts README naming
two deleted things (3), a section doc whose "cross-domain navs: none" was false and whose
dependencies were narrated rather than read from the csproj (4), a barcode spec still
claiming a top-level nav entry (5), and a gate-terminal spec that mis-owned the seeder
and told the account's history three times (6). The same claims sat in five files outside
the section (7). Comments narrating lane numbers and issue refs were cut (8), one dead JS
variable deleted (10), and three target invariants that nothing pinned now have tests (11).

# Development — G0 First Audit

**Section:** Development · **Kind:** vertical (new, dev-only; prod-excluded for DevLogin only — see G1.6) · **Audited:** 2026-08-05 @ 94535e688

**Headline: this row is a decision, not yet a code module.** The frozen-inventory record rules *"Move [DevLogin/DevSeed] to a new Development section that is not loaded in prod"* and lists extraction as open follow-up item #4 ("Extract DevLogin/DevSeed into the Development section with prod-excluded loading"). Today, `DevLoginController` and `DevSeedController` both declare `namespace Humans.Web.Controllers;` (confirmed by `grep -n "^namespace"` on both files) — the generic controllers namespace, not a `Development`-named one — and the four seeder classes they call (`DevelopmentBudgetSeeder`, `DevelopmentCampRoleSeeder`, `DevelopmentDashboardSeeder`, and `DevPersonaSeeder`, which `DevLoginController` injects at `DevLoginController.cs:21` for persona creation/repair) live in `Humans.Web.Infrastructure`. Prod-exclusion is only half-built (see G1.6), and there is no `Humans.Application.Services.Development` namespace, no owning service, and no `docs/sections/Development.md` — most G1/G3 predicates below are scored against files that exist but aren't yet organized as a section.

## G1 gap list

1. **`docs/sections/Development.md` doesn't exist** (predicate 7). Fix: write it once extraction (gap #2) lands, or as an interim doc-only step describing the current controller/seeder shape and the prod-exclusion mechanism. No-migration-needed: **y**.
2. **DevLogin/DevSeed haven't been extracted into a `Development`-named module** — both controllers and all four seeders (including `DevPersonaSeeder`) remain in the generic `Humans.Web.Controllers`/`Humans.Web.Infrastructure` namespaces. This is frozen-inventory follow-up item #4, confirmed still open by this audit, not new debt. Whoever moves `DevLoginController` must take `DevPersonaSeeder` with it — the controller injects it and calls its statics (`PersonaGuid`, `IsBarrioLeadSlug`, `IsCityPlanningSlug`), so leaving it behind splits the dev-login behaviour across two modules. No-migration-needed: **y**.
3. **Not yet in `reforge.surface-score.json`** (`'Development' in data['sections']` → `False`) — frozen-inventory follow-up #1, same gap as Gate/Settings. No-migration-needed: **y**.
4. **`DevSeedController` is still loaded in Production** (predicate 6) — the exclusion provider removes `DevLoginController` only, so half the dev controller surface reaches prod behind action-level guards rather than being absent from the MVC graph. Fix: generalise the provider to a set of dev-only controller types, or move both behind one dev-only application part when the extraction in gap #2 lands. No-migration-needed: **y**.
5. **Two dev seeders write Identity tables directly via `UserManager<User>`** (predicate 1) — `DevelopmentDashboardSeeder` (`CreateAsync` L282, `UpdateAsync` L308) and `DevPersonaSeeder` (`CreateAsync` L112, L331). Bypasses `IUserService` and therefore every Users-section invariant that lives above the Identity layer. Invisible to the analyzers/baselines because `UserManager` is neither a repository nor a `DbContext`. **Scope correction (2026-08-07):** an earlier revision of this gap also named `DevLoginController` as a writer. It isn't one — it injects `UserManager` but only calls `FindByIdAsync` (L84, L92, L115, L143) and delegates creation to `DevPersonaSeeder`. Whoever works this gap should not go looking for a write path in the controller. Fix: route dev-user creation through the Users section's own service, or record it as a sanctioned dev-only exception in `docs/sections/Development.md` when gap #1 lands. No-migration-needed: **y**.
6. **Three of the four seeders consume other sections' baselined entity-returning reads, and one mutates the entity it gets back** (predicate 3). Fix: migrate to the clean surfaces the owning sections already expose — `IBurnSettingsService` for event settings, `ITeamServiceRead` for team lookups — so the dev seeders stop depending on the two sections' known leaks. Sequencing: these are Shifts'/Teams' baseline rows to retire, so Development's move should follow, not lead, their read-split work. No-migration-needed: **y**.

## G3 gap list

1. **Three of the four Development seeders have zero dedicated unit tests** (predicate 2) — `DevelopmentBudgetSeeder`, `DevelopmentCampRoleSeeder` and `DevelopmentDashboardSeeder`'s business logic (which teams/budget-lines/camp-roles get created, idempotency on re-run) is entirely unverified except by manual use. `DevPersonaSeeder` is the exception and already has `DevPersonaSeederTests.cs`. Fix: add `DevelopmentBudgetSeederTests.cs`/etc. mocking the injected section service interfaces. No-migration-needed: **y**.
2. **`DevLoginController`'s own gating/persona-resolution logic has no direct unit test** — it's only exercised as integration-test *infrastructure*, so a regression there would surface as unrelated integration-test failures elsewhere rather than a clear, attributable failure. Fix: add a `DevLoginControllerTests.cs` covering `IsDevAuthEnabled()`/persona-not-found/guest-flow branches directly. No-migration-needed: **y**.
3. **No `Development` test grouping exists** (predicate 5). Not purely a consequence of gaps 1/2: `DevPersonaSeederTests.cs` already exists under `Humans.Web.Tests/Infrastructure/` and is ungrouped today, so the G5 move has real content to carry regardless of whether the missing seeder tests land first. Fix: create the `Development`-named grouping alongside the extraction in G1 gap #2 and move `DevPersonaSeederTests.cs` into it with `DevPersonaSeeder` itself — if the seeder moves and its test stays behind in the generic `Infrastructure/` folder, the coverage gets orphaned from the code it covers.

## G1 gap list

Gate's *table* ownership is clean — no entity-leak, join or grandfather findings, and all three owned tables stay behind `IGateRepository`. Three gaps: two documentation drifts (predicate 7) and one cross-section write (predicate 6).

1. **`docs/sections/Gate.md`'s Configuration list omits `Gate:RetentionDays`** — read by `GateRetentionJob.cs:25` with a 365-day default, and settable to disable the purge. Mentioned in the retention prose (`Gate.md:105`) but absent from the config list an operator would read. Fix: add it to `## Configuration` with the default and the disable value. No-migration-needed: **y**.
2. **`docs/sections/Gate.md`'s Cross-Section Dependencies omits `IAuditLogService`** — injected by `GateService.cs:38` for PIN audit writes. Fix: add the AuditLog line, matching how the other 15 section docs record it. No-migration-needed: **y**.

3. **Gate-terminal account provisioning writes Users/Auth state outside the Users service boundary** (predicate 6). `GateTerminalAccountSeeder` — reached only from `/Tickets/Admin/Gate` (`TicketsGateAdminController.cs:18`; `Program.cs:86` is the sole other reference) — creates the well-known `SystemUserIds.GateTerminal` Identity row with `UserManager.CreateAsync` (`GateTerminalAccountSeeder.cs:96`) and rotates its credentials with `ResetPasswordAsync` + `SetLockoutEnabledAsync` (L69, L73). Same analyzer blind spot as Development gap #5: `UserManager` is neither a repository nor a `DbContext`, so nothing flags it.

   **Materially better-behaved than the Development case, though, and the fix should not be copy-pasted from it.** Everything that *has* a service-layer path already uses one: the profile goes through `IProfileEditorService.SaveProfileAsync` (L106) specifically so `UserStateClassifier` lifts the account to Active, the consent clear goes through `IUserService.ApplyProfileOnboardingMutationAsync` (L122), and the credential set is audit-logged (`AuditAction.GateTerminalPasswordSet`, L75). What's left on `UserManager` is Identity-credential work — create the login row, reset the password, disable lockout — for which no `IUserService` equivalent exists, because `UserManager` *is* the Auth-section API for it. So "route it through the Users service" is not an available exit here without inventing credential-management surface on `IUserService`, which the reuse-first rule argues against for a single caller.

   Fix: record it as a **sanctioned Gate/Auth exception** in `docs/sections/Gate.md`, naming the three `UserManager` calls and why the account is a `User` row rather than a credential blob (per the class doc: "a real User row, not a person" — it signs in through the normal Identity path). No-migration-needed: **y**.

   *Open question for Peter (small):* the seeder is Web-layer infrastructure named for Gate but reached through a Tickets-routed controller, and no other scorecard mentions it. Recorded here because this scorecard is what pulled `TicketsGateAdminController` into scope — reassign to the Tickets scorecard if you'd rather the route own it.

Config back-propagation (frozen-inventory follow-up #1) remains open but is tracked there already, not fresh debt from this audit.

## G3 gap list

1. **No `GateRepositoryTests.cs` — repository coverage is only indirect, via an EF-InMemory harness** (predicate 1). Fix: add a dedicated repository test file against the real-Postgres shared fixture (#764/#766 scope), covering the `AdmitDedupeKey` unique-index race path that `docs/sections/Gate.md` itself flags as a known test gap ("the concurrent index-collision path isn't covered by unit tests — the EF in-memory provider can't enforce unique indexes"). No-migration-needed: **y**.
2. **`GateServiceTests` extends `ServiceTestHarness` and constructs a real `GateRepository` over EF-InMemory instead of mocking `IGateRepository`** (predicate 2) — same corrected pattern as Camps/Auth/Budget/Governance/Consent in the original G0 pass. Fix: convert to `Substitute.For<IGateRepository>()` per #766. No-migration-needed: **y** (test-only change).
3. **Gate-terminal credential provisioning has no test of any kind** (predicates 2/3, and the counterpart to G1 gap #3). Since this scorecard pulls `TicketsGateAdminController`/`GateTerminalAccountSeeder` into Gate's scope, G3 has to cover them too, and nothing does: the only test file in the repo naming either type is `tests/Humans.Application.Tests/Authorization/EndpointAuthorizationTests.cs`, which asserts the route's authorization attributes, not its behaviour. `AccountControllerGateLoginTests` covers sign-in *after* the account exists. So first-use provisioning, password rotation, the lockout-disable, the profile/consent setup and the two cache invalidations are all unverified — on a path that mints a real, signs-in-able account. Fix: add `GateTerminalAccountSeederTests.cs` covering provision-on-first-use, rotate-existing, and the rejected-password case that must leave the old credential intact (`SetPasswordAsync`'s validate-then-replace contract, `GateTerminalAccountSeeder.cs:64-71`). No-migration-needed: **y**.
4. **The vendor-checked-in dedupe signal is dead, and nothing tests it** (predicate 3) — a live code gap, not just missing coverage. `GateService.cs:79` reads `attendee.Status == TicketAttendeeStatus.CheckedIn`, while the sync that peterdrier#1059 added writes `TicketAttendee.CheckedInAt` and leaves `Status` at `Valid`; the scan card's vendor-duplicate warning therefore never appears. Already recorded in `docs/sections/Gate.md:97-104` and tracked in the debt-ledger inbox (2026-07-02) — surfaced here so the Gate backlog isn't read as repository-test work only. Admission correctness is unaffected: cross-device duplicate detection rests on the `gate_scan_events` unique index, which is the authority regardless. Fix: derive `CheckedInAtVendor` from `attendee.CheckedInAt is not null` (the backfill diff already keys off that field) and add the regression test the signal has never had. No-migration-needed: **y**.

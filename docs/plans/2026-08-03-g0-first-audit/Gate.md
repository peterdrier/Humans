## G3 gap list

1. **No `GateRepositoryTests.cs` — repository coverage is only indirect, via an EF-InMemory harness** (predicate 1). Fix: add a dedicated repository test file against the real-Postgres shared fixture (#764/#766 scope), covering the `AdmitDedupeKey` unique-index race path that `docs/sections/Gate.md` itself flags as a known test gap ("the concurrent index-collision path isn't covered by unit tests — the EF in-memory provider can't enforce unique indexes"). No-migration-needed: **y**.
2. **`GateServiceTests` extends `ServiceTestHarness` and constructs a real `GateRepository` over EF-InMemory instead of mocking `IGateRepository`** (predicate 2) — same corrected pattern as Camps/Auth/Budget/Governance/Consent in the original G0 pass. Fix: convert to `Substitute.For<IGateRepository>()` per #766. No-migration-needed: **y** (test-only change).
3. **The vendor-checked-in dedupe signal is dead, and nothing tests it** (predicate 3) — a live code gap, not just missing coverage. `GateService.cs:79` reads `attendee.Status == TicketAttendeeStatus.CheckedIn`, while the sync that peterdrier#1059 added writes `TicketAttendee.CheckedInAt` and leaves `Status` at `Valid`; the scan card's vendor-duplicate warning therefore never appears. Already recorded in `docs/sections/Gate.md:97-104` and tracked in the debt-ledger inbox (2026-07-02) — surfaced here so the Gate backlog isn't read as repository-test work only. Admission correctness is unaffected: cross-device duplicate detection rests on the `gate_scan_events` unique index, which is the authority regardless. Fix: derive `CheckedInAtVendor` from `attendee.CheckedInAt is not null` (the backfill diff already keys off that field) and add the regression test the signal has never had. No-migration-needed: **y**.

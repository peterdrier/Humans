# CORRECTIONS (2026-09-11). This block was wrong twice before it was right; both are recorded
# because the failure mode is instructive, and because a ledger that hides its own retractions is
# not an audit trail.
#   (1) It first claimed the token appeared in "exactly one commit in all of history" (d3bf4010,
#       the G5 move). FALSE. Gathered in a container whose clone was SHALLOW — truncated to
#       2026-06-17, months after this column was introduced — so `git log --all` silently searched
#       a recent slice. ALWAYS run `git rev-parse --is-shallow-repository` before believing any
#       `git log -S` result in a container, and `git fetch --unshallow` first.
#   (2) The correction then claimed five search predicates each returned no commits outside
#       migrations, among them `\.ShiftSignupId`. FALSE, and self-contradictory: that regex matches
#       the `.HasForeignKey(e => e.ShiftSignupId)` line the same block quotes. It returns five
#       commits. Both errors were Codex P1s on this PR.
# The lesson, since it outlived two rewrites: an over-specific claim is not stronger evidence, it
# is more surface to be wrong on. What follows is stated so that it can be checked, not counted.
# Evidence: gathered over full (unshallowed) history.
# The column was introduced by 23b0ec159 (#135, "add shift management system (Slices 1-3)"), which
# added the property, an FK relationship and the filtered index; the DB column arrives in
# 20260316210003_AddShiftManagement. Outside migration folders, every commit touching the token
# falls into exactly three kinds, and none of them is a read or a write of the value:
#   - declaration and EF configuration — 23b0ec159 (`public Guid? ShiftSignupId { get; set; }`,
#     `.HasForeignKey(e => e.ShiftSignupId)`,
#     `builder.HasIndex(e => new { e.ShiftSignupId, e.TemplateName })`,
#     `.HasFilter("\"ShiftSignupId\" IS NOT NULL")`), and 48ba18f3 (#1233), which cut the FK and
#     left the bare Guid column;
#   - ratchet baseline files (7eda846d6, 4ab40cd5d) carrying migration locators as text;
#   - documentation — section docs, freshness sweeps, and the FK-cut inventory.
# Assignment- and access-form searches (`ShiftSignupId *=`, `ShiftSignupId =`, `ShiftSignupId:`,
# `ShiftSignupId ==`) return only this PR's own commits outside migrations. No migration backfilled
# it either: no `migrationBuilder.Sql`, `UPDATE email_outbox` or `INSERT INTO email_outbox` line in
# any migration mentions the column. The only delete behaviour the FK ever carried was
# ON DELETE SET NULL (cut by 48ba18f3), which can only ever write NULL.
# Corroboration, independent of this run: the FK-cut inventory (deddd7b1f, #992/#1206,

# Gate — Authorization

| Controller | Scope | Roles | Source |
|---|---|---|---|
| `GateController` | Class | `TicketsAdmin, Admin, Board` OR the gate-terminal shared account (by well-known id) | `PolicyNames.ScannerAccess` (gate admissions terminal at `/Gate` — distinct from the read-only Scanner section: this one decides entry and writes the durable `gate_scan_events` record; the read actions `Index`, `Evaluate`, `Find`, `Claim` GET, `Search`, `Leaderboard` inherit the class-level policy) |
| `GateController.Decision` | Action | `TicketsAdmin, Admin` OR the gate-terminal shared account | `PolicyNames.GateAdmit` (POST — records the admission decision, attributed to the authenticated principal; supervisor overrides — too-early / unconfirmed-EE admit, child-without-ID waiver — additionally require the shared override PIN) |
| `GateController.Claim` (POST) / `ClaimPin` / `EndShift` | Action | `TicketsAdmin, Admin` OR the gate-terminal shared account | `PolicyNames.GateAdmit` (claims/releases the scanning session; `ClaimPin` verifies or enrols the staffer's personal 4-digit PIN via `IGateService` with per-target-user `GatePinThrottle` buckets; the verified user id is stamped into the session server-side — never from the request body). *Unreachable: no live page links into the claim flow, shelved under nobodies-collective/Humans#933; the deny paths above still hold* |
| `GateController.Admin` (GET/POST) / `SetStaffPin` / `ResetStaffPin` | Action | `TicketsAdmin, Admin` | `TicketsPolicies.Manage` (admin PIN enrolment/reset at `/Gate/Admin`; gate settings (cutoff, minor age threshold) live at `/Settings#gate`, same policy; the `Admin` POST is the save target of that tab; override authority comes from the shared `Gate:SupervisorPin`, never from staff PINs) |
| `GateController.Undo` (POST) | Action | `TicketsAdmin, Admin` OR the gate-terminal shared account | `PolicyNames.GateAdmit` (reverses a live admit by barcode at the gate; requires the shared `Gate:SupervisorPin`, attributed to the authenticated principal) |
| `GateReportController` | Class | `TicketsAdmin, Admin, Board` | `TicketsPolicies.Read` (arrivals report at `/Gate/Report`; `Index` inherits) |
| `GateReportController.Undo` (POST) | Action | `TicketsAdmin, Admin` | `TicketsPolicies.Manage` (reverses a recorded admit by scan id; a reason is required; the view shows the control only to `Manage`) |
| `GateVendorBackfillAdminController` | Class | `Admin` | `PolicyNames.AdminOnly` (one-off vendor check-in backfill page at `/Gate/Admin/VendorCheckInBackfill`; `Index`, `RunOne`, `Run` all inherit) |

`GateAdmit` is `ScannerAccess` minus Board: the durable gate write surface never rides on the read-only Scanner gate, and Board reads the gate without admitting anyone. Override supervisors are Admin and TicketsAdmin. Supervisor overrides inside `Decision` are a second factor on top of the policy — the shared `Gate:SupervisorPin` config value, verified inside `GateService.RecordDecisionAsync` with a fixed-time hash compare and brute-force-throttled via `GatePinThrottle` (fail-closed when unconfigured) — not an identity check. `GateController.Undo` verifies the same shared PIN through the same throttle. `GateController.Claim` (POST) / `ClaimPin` also requires the claimant to be a real active member (`UserService.GetUserInfoAsync(...).IsActive`).
